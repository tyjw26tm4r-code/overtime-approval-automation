# Power Apps 创建

在这一步，我们将详细配置 Power Automate 的三层审批流程，为加班申请自动化审批系统做好准备。

---

## 📋 概述

**什么是 Power Automate？**

Power Automate 是微软的自动化工作流平台，能够：
- 自动处理重复性任务
- 连接多个应用程序
- 创建条件分支逻辑
- 发送通知和邮件
- 更新数据库记录

**本文档的目的：**

在构建完整的 Power Automate 流程之前，我们需要：
1. 理解审批流程的设计要求
2. 配置必要的连接和权限
3. 准备流程所需的数据源
4. 设计错误处理机制
5. 规划流程的监控和维护

## 🎯 审批流程设计

### 审批层级结构

```
┌─────────────────────────────────────────────────────────────┐
│                      员工提交加班申请                         │
│                    (通过 Power Apps)                        │
└────────────────────────┬────────────────────────────────────┘
                         │
                    存储到 SharePoint
                         │
        ┌────────────────▼────────────────┐
        │   第一层审批：直属主管           │
        │  (Immediate Manager)           │
        └────────────────┬────────────────┘
                         │
        ┌────────────────▼────────────────┐
        │   第二层审批：部门经理           │
        │  (Department Manager)          │
        └────────────────┬────────────────┘
                         │
        ┌────────────────▼────────────────┐
        │   第三层审批：HR 负责人          │
        │  (HR Administrator)            │
        └────────────────┬────────────────┘
                         │
        ┌────────────────▼────────────────┐
        │   审批完成                       │
        │  - 更新状态为"已批准"            │
        │  - 发送确认邮件给申请人          │
        └────────────────────────────────┘
```

### 审批规则

| 规则 | 说明 |
|------|------|
| **串行审批** | 必须按顺序进行，前一层批准后才能进入下一层 |
| **全部通过** | 所有三层都必须批准，申请才能最终通过 |
| **任何拒绝** | 任何一层拒绝，流程立即终止，申请人被通知 |
| **时间限制** | 每层审批应在 3 天内完成（可选） |
| **审计记录** | 所有审批意见和时间都要记录 |

## 🔧 前置条件和配置

### 1. 权限配置

**必需的权限：**

| 角色 | 权限 | 用途 |
|------|------|------|
| **SharePoint Owner** | 完全控制 | 创建和管理列表 |
| **流程创建者** | 编辑 | 创建和修改 Power Automate 流程 |
| **审批者** | 读取 | 查看审批请求 |
| **申请人** | 编辑 | 提交和查看自己的申请 |

**配置步骤：**

1. 打开 SharePoint 站点设置
2. 进入"权限" → "站点权限"
3. 确保所有用户都有相应的访问权限
4. 创建特殊用户组（如"审批人组"）便于权限管理

### 2. 数据源连接

**需要连接的系统：**

```
┌──────────────────┐
│   SharePoint     │ ← 存储申请和审批信息
└────────┬─────────┘
         │
┌────────▼─────────┐
│   Office 365     │ ← 发送邮件通知
│   Outlook        │
└────────┬─────────┘
         │
┌────────▼─────────┐
│   Excel/表格     │ ← 查询员工信息
└──────────────────┘
```

**连接配置：**

```
在 Power Automate 中：
1. 点击左侧菜单 "我的流" 
2. 在右上角找到"数据" → "连接"
3. 添加以下连接：
   - SharePoint Online
   - Office 365 Outlook
   - Excel Online (如果使用 Excel 作为数据源)
```

### 3. SharePoint 列表结构

确保您的 SharePoint 列表包含以下字段：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| **申请ID** | 文本 | 唯一标识 |
| **申请人** | 文本 | 员工名字 |
| **申请人邮箱** | 电子邮件 | 用于通知 |
| **申请日期** | 日期 | 申请提交时间 |
| **加班日期** | 日期 | 加班的日期 |
| **加班时间** | 时间 | 加班的具体时间 |
| **加班原因** | 文本 | 说明理由 |
| **部门** | 文本 | 员工部门 |
| **直属主管** | 文本 | 主管名字 |
| **主管邮箱** | 电子邮件 | 主管邮件地址 |
| **主管审批状态** | 选择 | 待审批/已批准/已拒绝 |
| **主管审批意见** | 文本 | 审批备注 |
| **主管审批时间** | 日期 | 主管完成审批时间 |
| **经理审批状态** | 选择 | 待审批/已批准/已拒绝 |
| **经理审批意见** | 文本 | 审批备注 |
| **经理审批时间** | 日期 | 经理完成审批时间 |
| **HR审批状态** | 选择 | 待审批/已批准/已拒绝 |
| **HR审批意见** | 文本 | 审批备注 |
| **HR审批时间** | 日期 | HR 完成审批时间 |
| **最终状态** | 选择 | 待审批/已批准/已拒绝 |
| **审批完成时间** | 日期 | 整个流程完成时间 |

## 🚀 操作步骤

### 第一步：准备数据和变量

在创建流程前，我们需要定义流程中使用的变量。

**常用变量：**

```
变量名                类型        说明
──────────────────────────────────────────
申请人名字            字符串      从 SharePoint 列表获取
申请人邮箱            字符串      从 SharePoint 列表获取
直属主管邮箱          字符串      从 Excel 或列表查询
部门经理邮箱          字符串      从 Excel 或列表查询
HR负责人邮箱          字符串      预设的常量
审批意见              字符串      存储审批人的反馈
审批时间              日期时间    记录审批完成时间
审批状态              字符串      已批准/已拒绝/待审批
```

**如何设置变量：**

1. 在 Power Automate 流程中，点击 "+ 新建步骤"
2. 搜索 "初始化变量"
3. 配置每个变量的名称、类型和初始值

### 第二步：配置查找员工信息的逻辑

为了自动查找员工的直属主管和部门经理，我们需要设置查询逻辑。

**方式 1：使用 Excel 表格（推荐）**

```
步骤 1：添加 "获取 Excel 表中的行" 操作
步骤 2：配置参数
  - 位置：选择 SharePoint 站点
  - 文档库：选择包含 Excel 的库
  - 表：选择 EmployeeInfo 表
  - 过滤查询：邮箱 = [申请人邮箱]
步骤 3：在结果中提取主管邮箱
  - 使用表达式：
    first(body('获取_Excel_表中的行')['value'])?['主管邮箱']
```

**方式 2：使用 SharePoint 列表查询**

```
步骤 1：添加 "获取项" 操作（SharePoint）
步骤 2：配置参数
  - 网站地址：选择 SharePoint 站点
  - 列表名：EmployeeInfo
  - 过滤查询：邮箱 eq '[申请人邮箱]'
步骤 3：提取需要的字段
  - 主管邮箱：从查询结果中获取
  - 部门：从查询结果中获取
```

### 第四步：配置条件分支

**主要条件逻辑：**

```
1. 检查申请是否有效
   条件：申请ID 不为空 AND 申请人邮箱 不为空
   → 是：继续流程
   → 否：发送错误通知

2. 检查是否是新申请
   条件：主管审批状态 = 待审批
   → 是：发送给主管
   → 否：检查是否需要更新

3. 处理主管审批结果
   条件：主管批准 = 是
   → 是：发送给经理
   → 否：标记为拒绝，通知申请人

4. 处理经理审批结果
   条件：经理批准 = 是
   → 是：发送给 HR
   → 否：标记为拒绝，通知申请人

5. 处理 HR 审批结果
   条件：HR 批准 = 是
   → 是：更新最终状态为已批准，通知申请人
   → 否：标记为拒绝，通知申请人
```

### 第五步：错误处理和异常管理

**可能的错误情况：**

| 错误 | 原因 | 处理方式 |
|------|------|---------|
| **邮箱不存在** | 审批人邮箱格式错误 | 记录错误日志，发送告警邮件给 IT |
| **查询超时** | Excel 表格过大 | 优化查询条件，添加分页处理 |
| **权限不足** | 用户无权限访问 | 检查 SharePoint 权限设置 |
| **邮件发送失败** | 邮件服务异常 | 重试 3 次，最后写入日志 |

**错误处理配置：**

```
在每个关键步骤后添加：

1. 配置运行后操作
2. 选择 "如果失败"
3. 添加以下操作：
   - 发送邮件给 IT 或管理员
   - 记录到 SharePoint 错误日志
   - 更新项目状态为 "待处理"
```

## ⚠️ 常见配置错误

| 错误 | 症状 | 解决方案 |
|------|------|---------|
| 邮箱查询失败 | 流程运行失败 | 检查 Excel 表列名是否匹配，确保邮箱字段存在 |
| 条件判断错误 | 流程走错分支 | 检查条件表达式语法，使用正确的操作符 |
| 字段映射错误 | 更新失败 | 验证 SharePoint 列表字段名称与流程中的字段匹配 |
| 权限问题 | 无法更新项目 | 确保流程运行账户有足够权限 |
| 时间格式错误 | 日期不正确 | 使用 formatDateTime 函数格式化日期 |
